## 0. この文書について

この文書は、R5RS Scheme から機能を削った小さな言語（以下「本言語」）を定める。
構成は R5RS に倣い、非形式的な記述 (1〜6 章) と形式的な記述 (7・8 章) からなる。
両者が食い違う場合は形式的な記述を正とする。

R5RS の該当箇所は「R5RS §x.y」の形で示す。

### 0.1 用語

R5RS §1.3.2 の用語法をそのまま使う。

- **エラーが通知される**: 処理系はそのエラーを検出して報告しなければならない。
  本言語では、すべてのエラーについてこの表現を用いる (9 章)。
  報告するのはエラーが起きたことだけで、エラーの種類は報告しない (9.1 節)。
- **未規定** (unspecified): 何らかの値に評価されるが、どの値かは処理系に依存する。
- **実装制限の違反を報告してもよい**: 処理系の制限で正しいプログラムを実行できないとき、その旨を報告してよい。

## 1. 概要

### 1.1 設計方針

1. **R5RS の部分集合とする。**
   本言語の正しいプログラムは R5RS の正しいプログラムでもあり、
   その実行結果は R5RS が許す結果のどれか一つと一致する。
   (R5RS が未規定としている所を本言語で一つに決めるのは構わない。)
2. **扱う値は 整数・雑値・手続き・ペア の 4 種類に限る。**
   値のドメインは次のとおり。
   ```
   E = Z + Ep + M + F
   ```  
   R5RS の `E = Q + H + R + Ep + Ev + Es + M + F` から、
   シンボル Q・文字 H・ベクタ Ev・文字列 Es を除き、数 R を整数 Z に絞ったものである。
3. **原始式は 変数参照・定数・手続き呼出し・`lambda`・`if`・`set!`・`letrec` の 7 種類だけとする。**
   派生式・マクロは持たない。
   代入は変数に対する `set!` だけで、ペアの中身は書き換えられない。
4. **評価順序は左から右に固定する。**
   R5RS の意味論で評価順序の未規定さを表していた `permute` / `unpermute` は不要になる。
5. **標準手続きの引数の個数は固定とする。**
   可変長引数は持たない。たとえば `+` はちょうど 2 引数をとる。

### 1.2 R5RS との違い

| 項目 | R5RS | 本言語 |
|---|---|---|
| 値の型 | ブーリアン, ペア, シンボル, 数, 文字, 文字列, ベクタ, ポート, 手続き, 空リスト | ブーリアン, **整数**, ペア, 手続き, 空リスト |
| 数 | 数値の塔 (複素数〜整数, 正確/不正確) | 整数のみ (正確) |
| 定数 | 任意のデータ (`quote`) | 整数, `#t`, `#f`, `'()` のみ |
| 原始式 | 変数, 定数, 呼出し, `lambda`, `if`, `set!` | 変数, 定数, 呼出し, `lambda`, `if`, `set!`, `letrec` |
| `lambda` の仮引数 | 固定・可変長・残余引数 | 固定個数のみ |
| `lambda` の本体 | 内部定義 + 式の列 | 式 1 個 |
| `if` | 代替部は省略可 | 代替部は必須 |
| `letrec` | 派生式 / 初期値は任意の式 | 原始式 / 初期値は `lambda` 式に限る |
| 派生式 (`let`, `cond`, `begin` 等), マクロ | あり | なし |
| 代入 | `set!`, `set-car!`, `set-cdr!` 等 | `set!` のみ (ペアは書換え不可能, 標準手続きの名前には代入不可) |
| 定義 | トップ・レベル + 内部定義, `(define (f x) ...)` 形式あり | トップ・レベルの `(define 変数 式)` のみ |
| 評価順序 | 未規定 | 左から右 |
| 継続・多値 | `call-with-current-continuation`, `values`, `dynamic-wind` あり | `call-with-current-continuation` のみ (継続に渡せる値は 1 個) |
| 入出力 | ポート, `read`, `write` 等 | `display`, `newline` のみ (常に標準出力) |
| エラー | 検出は多くの場合任意 | すべて検出・通知する |

## 2. 字句規約

R5RS 第 2 章に従う。ただし次の点を変える。

### 2.1 トークン

本言語のトークンは次の 6 種類だけである。

```
<トークン> ::= <識別子> | <ブーリアン> | <整数> | ( | ) | '
```

R5RS のトークンのうち、文字 (`#\a`)、文字列 (`"..."`)、ベクタ開始 (`#(`)、
準引用関係 (`` ` `` `,` `,@`)、ドット (`.`) は持たない。

### 2.2 識別子

識別子の綴りは R5RS §2.1 / §7.1.1 と同じである。

```
<識別子>      ::= <頭文字> <後続文字>* | + | - | ...
<頭文字>      ::= <英字> | ! | $ | % | & | * | / | : | < | = | > | ? | ^ | _ | ~
<後続文字>    ::= <頭文字> | <数字> | + | - | . | @
<英字>        ::= a | b | ... | z
<数字>        ::= 0 | 1 | ... | 9
```

R5RS と同じく、英大文字と英小文字は区別しない (`Fact` と `fact` は同じ識別子)。

### 2.3 ブーリアン

```
<ブーリアン> ::= #t | #f
```

### 2.4 整数

10 進表記で、符号を付けてもよい。

```
<整数> ::= <符号> <数字>+
<符号> ::= <空> | + | -
```

R5RS にある基数接頭辞 (`#x` 等)、正確性接頭辞 (`#e` `#i`)、小数点、指数、`#` による桁埋めは持たない。
`+` と `-` は単独では識別子であり、直後に数字が続くときに限り整数の一部になる。

### 2.5 空白と注釈

R5RS §2.2 と同じ。
空白 (スペース・改行) と注釈 (`;` から行末まで) は任意のトークンの間に置くことができ、
識別子・整数・ブーリアンの直後には区切り文字 (空白, `(`, `)`, `;`) が必要である。

## 3. 基本概念

### 3.1 変数・束縛・領域

R5RS §3.1 に従う。本言語は静的スコープを持ち、変数を束縛する構文は
`lambda`・`letrec`・`define` の 3 つである。

- `lambda` の仮引数の束縛の領域は、その `lambda` 式の本体である。
- `letrec` の変数の束縛の領域は、その `letrec` 式全体である。
- `define` の変数の束縛の領域は、プログラム全体である (5 章)。

### 3.2 構文キーワード

`lambda` `if` `set!` `letrec` `define` `quote` は本言語の構文キーワードである。

1.1 節の方針 1 を守るため、R5RS の構文キーワードもすべて予約し、変数として使うことはできない。

```
quote lambda if set! begin cond and or case let let* letrec do delay
quasiquote else => define unquote unquote-splicing
define-syntax let-syntax letrec-syntax syntax-rules
```

### 3.3 型の分離性

どの値も次の型のうち 2 つ以上に属することはない (R5RS §3.2)。

| 型 | 判定する述語 | 値 |
|---|---|---|
| ブーリアン | (なし) | `#t`, `#f` |
| 整数 | (なし) | …, -1, 0, 1, … |
| ペア | `pair?` | `cons` が返す値 |
| 手続き | (なし) | `lambda` 式の値, 標準手続き, 継続を表す手続き (6.7 節) |
| 空リスト | `null?` | `'()` |

これらのほかに、`display` と `newline` が返し、`set!` 式の値にもなる **未規定値** がある。どの型にも属さない。

R5RS の `symbol?` `char?` `string?` `vector?` `port?` に相当する型は持たない。

### 3.4 真と偽

R5RS §6.3.1 と同じく、`#f` だけが偽で、それ以外の値 (`0` や `'()` を含む) はすべて真である。

### 3.5 記憶モデル

R5RS §3.4 に従う。変数とペアは場所 (location) を表す。

変数の場所に格納された値は `set!` (4.7 節) で書き換えられる。
`lambda` の仮引数、`letrec` の変数、`define` の変数のどれも代入の対象になる。
手続きは変数の場所そのものを記憶するので、代入の結果はその変数を参照するすべての手続きから見える。

一方、ペアの car / cdr の場所に一度格納した値は書き換えられない (`set-car!` / `set-cdr!` を持たない)。したがって:

- R5RS の、ペアが書換え可能かどうかを示すフラグは要らない。
- 循環したリスト構造は作れない。

`define` の変数は、`set!` のほかに継続でも格納し直されることがある。
定義の式の評価中に捕まえた継続 (6.7 節) を後で呼び出すと、
その定義から先が再び実行され、変数の場所に値が格納し直される (8.4 節の 𝒟)。
これは R5RS でトップ・レベルの定義が代入として振る舞うのと同じである。

代入や再格納で変数の値が変わっても、ペアの中身は変わらないので、循環したリスト構造は作れない。
(ペアの中に、そのペア自身を指す変数を参照する手続きを入れることはできるが、`display` は手続きの中をたどらない。)

場所は、ペアや手続きの同一性 (`eq?`) を区別するために必要である。

### 3.6 真正な末尾再帰

R5RS §3.5 と同じく、処理系は真正に末尾再帰的でなければならない。
本言語にはループ構文がないので、繰り返しはすべて末尾呼出しで書くことになる。

末尾文脈は次のように帰納的に定める。

- `(lambda (<変数>*) <末尾式>)` の本体は末尾文脈にある。
- `(if <式> <末尾式> <末尾式>)` が末尾文脈にあるとき、帰結部と代替部は末尾文脈にある。
- `(letrec (<束縛>*) <末尾式>)` が末尾文脈にあるとき、本体は末尾文脈にある。

末尾文脈にある手続き呼出しを末尾呼出しという。

また R5RS §3.5 と同じく、`call-with-current-continuation` が引数の手続きを呼び出す呼出しも末尾呼出しとして扱う (6.7 節)。

## 4. 式

### 4.1 変数参照

```
<変数>
```

変数が束縛されている場所に格納されている値を返す。

- どこでも束縛されていない変数 (未束縛変数) を参照するプログラムは正しくない。
  処理系は **実行前に** このエラーを通知しなければならない。
- `define` で束縛されているが、まだ値が格納されていない変数を参照すると、
  実行時にエラーが通知される (5.2 節)。

### 4.2 定数

```
<整数> | #t | #f | '()
```

整数とブーリアンはそれ自身に評価される。`'()` は空リストに評価される。

`'` の後に書けるのは `()` だけである。`'a` や `'(1 2)` は構文エラーである。
`'` と `(` の間、`(` と `)` の間に空白を置いてもよい (R5RS と同じ)。
`(quote ())` という書き方は持たない。

### 4.3 手続き呼出し

```
(<演算子> <オペランド>*)
```

まず演算子を評価し、次にオペランドを **左から右へ** 順に評価する。
その後、演算子の値である手続きに、オペランドの値を引数として渡す。

- 演算子の値が手続きでなければ、エラーが通知される。
- 引数の個数が手続きの期待する個数と違えば、エラーが通知される。
- `()` は式ではない (R5RS と同じ)。

評価順序を固定したので、副作用の順番を引数の並びで制御できる。

```scheme
((lambda (a b) b) (display 1) (newline))   ; "1" を出力してから改行する
```

### 4.4 lambda 式

```
(lambda (<変数>*) <式>)
```

- 仮引数は 0 個以上の変数の並びである。同じ変数が 2 回以上現れてはならない。
- 本体はちょうど 1 個の式である。

lambda 式を評価すると、そのときの環境を記憶した手続きが返る。
手続きを呼び出すと、記憶した環境を、各仮引数を新しい場所に束縛して拡張し、
対応する引数をそれらの場所に格納して、その環境で本体を評価する。本体の値が呼出しの値になる。

lambda 式を評価するたびに、手続きには新しい場所が目印として付けられる。`eq?` はこの目印で手続きを区別する。

### 4.5 条件式

```
(if <テスト> <帰結部> <代替部>)
```

まずテストを評価する。真 (3.4 節) であれば帰結部を、偽であれば代替部を評価し、その値を返す。
代替部は省略できない。

### 4.6 letrec 式

```
(letrec ((<変数> <lambda 式>)*) <式>)
```

- 束縛される変数は互いに異なっていなければならない。
- 各初期値は lambda 式でなければならない。

各変数を新しい場所に束縛して環境を拡張し、その環境で各 lambda 式を左から右へ評価して、
対応する場所に格納する。その後、同じ環境で本体を評価し、その値を返す。

初期値は lambda 式に限られ、lambda 式の評価では変数を参照しないので、
値が格納される前の変数を `letrec` の中で参照することはない。
この制限により、相互再帰する手続きを安全に定義できる。

### 4.7 代入

```
(set! <変数> <式>)
```

R5RS §4.1.6 と同じ。式を評価し、その値を変数が束縛されている場所に格納する。`set!` 式の値は未規定値である。

- 変数は、`set!` 式を囲む lambda 式・letrec 式、またはプログラムの定義で束縛されていなければならない (7.1 節の制約 5)。
  初期環境で束縛されているだけの標準手続きの名前には代入できない。違反は **実行前に** 通知される。
  定義によって束縛し直した名前 (5.1 節) には代入できる。
- `define` で束縛されているが、まだ値が格納されていない変数に代入すると、
  式を評価した後でエラーが通知される (R5RS §5.2.1 で、定義されていない変数への `set!` がエラーであることに合わせた)。
- 式は末尾文脈にない (3.6 節)。

```scheme
(define seq (lambda (a b) b))
(define x 1)
(seq (set! x (+ x 1))
     (display x))          ; 出力: 2
```

## 5. プログラム構造

### 5.1 プログラム

```
<プログラム> ::= <定義>* <式>
<定義>       ::= (define <変数> <式>)
```

プログラムは、0 個以上の定義と、最後に置く 1 個の式 (主式) からなる。
定義はトップ・レベルにだけ置くことができる。lambda の本体などの内部には置けない。

- 1 つのプログラムの中で、同じ変数を 2 回以上定義してはならない。
- 定義によって標準手続きの名前 (6 章) を束縛し直してもよい。
  その場合、プログラム全体でその名前は定義された値を指す。
- R5RS の `(define (<変数> <仮引数>*) <本体>)` 形式は持たない。

### 5.2 プログラムの実行

1. 定義されている変数をすべて、新しい場所に束縛する。この時点ではまだ値は格納されていない。
   これらの束縛は、プログラムの中の各定義と主式のすべてから見える。
2. 定義を上から順に実行する。各定義では式を評価し、その値を変数の場所に格納する。
3. 主式を評価する。

ステップ 2 で、まだ値が格納されていない変数を参照するとエラーが通知される。

```scheme
(define f (lambda () g))   ; よい: g は呼び出されるまで参照されない
(define g 1)
(define a b)               ; エラー: b はまだ値を持たない
(define b 2)
```

### 5.3 処理系の振舞

- 処理系は、プログラムの実行中に `display` / `newline` が生成した出力を、生成した順に標準出力に書く。
- 主式の値は出力しない。結果を見たいときは主式で `display` を使う。
- エラーが通知されたら、その時点で実行をやめ、エラーが起きたことだけを報告する (9.1 節)。
  それまでに書いた出力は取り消さない。

## 6. 標準手続き

初期環境では、次の 22 個の変数が標準手続きに束縛されている。引数の個数はすべて固定である。

| 分類 | 手続き | 引数 | 結果 |
|---|---|---|---|
| 算術 | `(+ n1 n2)` `(- n1 n2)` `(* n1 n2)` | 整数 2 個 | 整数 |
| 除算 | `(quotient n1 n2)` `(remainder n1 n2)` `(modulo n1 n2)` | 整数 2 個 (n2 ≠ 0) | 整数 |
| 比較 | `(= n1 n2)` `(< n1 n2)` `(> n1 n2)` `(<= n1 n2)` `(>= n1 n2)` | 整数 2 個 | ブーリアン |
| 述語 | `(zero? n)` | 整数 1 個 | ブーリアン |
|  | `(not obj)` | 任意 1 個 | ブーリアン |
|  | `(eq? obj1 obj2)` | 任意 2 個 | ブーリアン |
| ペア | `(cons obj1 obj2)` | 任意 2 個 | ペア |
|  | `(car pair)` `(cdr pair)` | ペア 1 個 | 任意 |
|  | `(null? obj)` `(pair? obj)` | 任意 1 個 | ブーリアン |
| 出力 | `(display obj)` | 任意 1 個 | 未規定値 |
|  | `(newline)` | なし | 未規定値 |
| 継続 | `(call-with-current-continuation proc)` | 手続き 1 個 | 任意 |

引数の個数が違う場合、または引数の型が表と違う場合は、エラーが通知される。

### 6.1 算術

`+` `-` `*` は 2 つの整数の和・差・積を返す。`(- n)` のような 1 引数の呼出しはエラーである。

### 6.2 除算

R5RS §6.2.5 と同じ。n2 が 0 のときはエラーが通知される。

- `(quotient n1 n2)`: n1/n2 を 0 の方向に丸めた整数
- `(remainder n1 n2)`: `n1 - n2 × (quotient n1 n2)`。符号は n1 と同じになる
- `(modulo n1 n2)`: `n1 - n2 × ⌊n1/n2⌋`。符号は n2 と同じになる

```scheme
(quotient 17 -5)    ⟹ -3
(remainder 17 -5)   ⟹ 2
(modulo 17 -5)      ⟹ -3
```

### 6.3 比較・述語

- `=` `<` `>` `<=` `>=` は 2 つの整数の大小関係が成り立てば `#t`、そうでなければ `#f` を返す。
- `(zero? n)` は n が 0 なら `#t` を返す。
- `(not obj)` は obj が `#f` なら `#t`、それ以外なら `#f` を返す。
- `(null? obj)` は obj が空リストなら `#t` を返す。
- `(pair? obj)` は obj がペアなら `#t` を返す。

### 6.4 eq?

`(eq? obj1 obj2)` は次の場合に `#t`、それ以外の場合に `#f` を返す。

| obj1, obj2 | `#t` となる条件 |
|---|---|
| ともに整数 | 数として等しい |
| ともにブーリアン / 空リスト / 未規定値 | 同じ値である |
| ともにペア | 同じ `cons` 呼出しで作られた (car と cdr の場所が同じ) |
| ともに手続き | 同じ lambda 式の同じ評価で作られた、同じ標準手続きである、または同じ `call-with-current-continuation` 呼出しで作られた継続である |

R5RS では整数に対する `eq?` の結果は処理系依存だが、本言語では数として等しいかどうかで決める。
これは R5RS が許す振舞の一つである。

### 6.5 ペア

- `(cons obj1 obj2)` は、car が obj1、cdr が obj2 の新しいペアを返す。
- `(car pair)` / `(cdr pair)` はペアの car / cdr を返す。
  引数がペアでない場合 (空リストを含む) はエラーが通知される。

### 6.6 出力

- `(display obj)` は obj の外部表現 (8.8 節) を標準出力に書き、未規定値を返す。
- `(newline)` は改行を標準出力に書き、未規定値を返す。

R5RS の、省略可能なポート引数は持たない。

```scheme
(display (cons 1 (cons 2 '())))   ; 出力: (1 2)
(display (cons 1 2))              ; 出力: (1 . 2)
(display #f)                      ; 出力: #f
```

### 6.7 継続

R5RS §6.4 の `call-with-current-continuation` と同じ。ただし次の点を定める。

`(call-with-current-continuation proc)` は、現在の継続を表す手続き (以下「継続手続き」) を作り、
それを唯一の引数として proc を呼び出す。proc の呼出しの値が、`call-with-current-continuation` の呼出しの値になる。

- proc が手続きでなければ、エラーが通知される。
  proc が 1 引数の手続きでなければ、通常の手続き呼出しと同じく引数の個数違いのエラーになる。
- proc の呼出しは末尾呼出しである (3.6 節)。
- 継続手続きはちょうど 1 個の引数をとる。
  呼び出すと、その時点の継続を捨て、引数の値を `call-with-current-continuation` の呼出しの値として計算を続ける。
- 継続手続きに 1 個以外の引数を渡すと、エラーが通知される。
  (R5RS では、1 個以外の値を継続に渡したときの振舞は未規定である。本言語ではエラーに決める。)
- 継続手続きは、`call-with-current-continuation` の呼出しが戻った後でも、何度でも呼び出せる (R5RS と同じ)。
  処理系は、一度しか呼べない継続 (one-shot) や、脱出にしか使えない継続 (escape-only) で済ませてはならない。
- 継続手続きを呼び出しても、それまでに `display` / `newline` で書いた出力は取り消されない。
- `call-with-current-continuation` を呼び出すたびに、新しい継続手続きが作られる。`eq?` はこれらを区別する (6.4 節)。

R5RS の多くの処理系にある `call/cc` という別名は、R5RS では定められていないので持たない (方針 1)。
必要なら `(define call/cc call-with-current-continuation)` と定義すればよい。
R5RS の `dynamic-wind` と `values` / `call-with-values` も持たない。

```scheme
; 脱出: (k 2) を呼んだ時点で (+ 10 □) は捨てられる
(display (+ 1 (call-with-current-continuation (lambda (k) (+ 10 (k 2))))))
; 出力: 3
```

```scheme
; 再突入: 戻った後の継続を呼び直す
(define seq (lambda (a b) b))
((lambda (r)
   (seq (display (pair? r))
        (if (pair? r) ((car r) 5) (display r))))
 (call-with-current-continuation (lambda (k) (cons k '()))))
; 出力: #t#f5
```

2 つ目の例では、最初 r は継続手続きを包んだペアなので `#t` を出力する。
次に `((car r) 5)` で継続を呼び直すと、r が 5 となって `(lambda (r) ...)` の呼出しがやり直され、`#f` と `5` を出力する。
最初に出力した `#t` は取り消されない。

## 7. 形式的構文

拡張 BNF で書く。`<x>*` は 0 回以上、`<x>+` は 1 回以上の繰返しを表す。
字句は 2 章で定めた。

```
<プログラム>   ::= <定義>* <式>
<定義>         ::= (define <変数> <式>)

<式>           ::= <定数>
                 | <変数>
                 | (lambda (<変数>*) <式>)
                 | (if <式> <式> <式>)
                 | (set! <変数> <式>)
                 | (letrec (<束縛>*) <式>)
                 | (<式> <式>*)

<定数>         ::= <整数> | <ブーリアン> | ' ( )
<束縛>         ::= (<変数> <lambda式>)
<lambda式>     ::= (lambda (<変数>*) <式>)
<変数>         ::= 3.2 節の構文キーワードでない <識別子>
```

### 7.1 静的な制約

BNF に加えて、正しいプログラムは次の制約を満たさなければならない。
処理系は、違反があれば実行前にエラーを通知しなければならない。

1. 1 つの lambda 式の仮引数の中に、同じ変数が 2 回以上現れない。
2. 1 つの letrec 式で束縛する変数の中に、同じ変数が 2 回以上現れない。
3. 1 つのプログラムの中に、同じ変数の定義が 2 回以上現れない。
4. すべての変数参照が、それを囲む lambda / letrec、プログラムの定義、または初期環境 (6 章) のどれかで束縛されている。
5. すべての `set!` 式の変数が、それを囲む lambda / letrec、またはプログラムの定義で束縛されている (初期環境は含めない)。

## 8. 形式的意味論

R5RS §7.2 の表示的意味論を、本言語向けに簡単にしたものである。継続渡し形式と記憶 (store) を使う点は R5RS と同じである。

### 8.1 記法

R5RS §7.2 と同じ記法を使う。

```
⟨…⟩          列をつくる
s ↓ k        列 s の第 k 要素 (1 から数える)
#s           列 s の長さ
s § t        列 s と列 t の連結
s † k        列 s から最初の k 要素を除いた列
t → a, b     McCarthy の条件式 "if t then a else b"
ρ[x/i]       i の代わりに x を持つ ρ
x in D       ドメイン D への x の単射
x | D        ドメイン D への x の射影
```

`true`, `false` などの M の要素を E の値として書くときは、`in E` を省略する。

### 8.2 抽象構文

```
K ∈ Con     定数 (整数, #t, #f, '())
I ∈ Ide     識別子 (変数)
E ∈ Exp     式
L ∈ Lam     lambda 式 (Lam ⊆ Exp)
D ∈ Def     定義
P ∈ Prog    プログラム

Exp  → K | I | (E0 E*)
     | (lambda (I*) E0)
     | (if E0 E1 E2)
     | (set! I E0)
     | (letrec ((I L)*) E0)
Lam  → (lambda (I*) E0)
Def  → (define I E)
Prog → D* E0
```

R5RS にあるコマンド Γ (式の列) は、本言語には要らない。

### 8.3 ドメイン

```
α ∈ L                         場所
ν ∈ N                         自然数
    T  = {false, true}        ブーリアン (記憶の使用中フラグに使う)
    Z                         整数
    Ep = L × L                ペア
    M  = {false, true, null, undefined, unspecified}
                              雑値
φ ∈ F  = L × (E* → K → C)    手続き値
ε ∈ E  = Z + Ep + M + F       式の値
σ ∈ S  = L → (E × T)         記憶
ρ ∈ U  = Ide → L             環境
θ ∈ C  = S → A               コマンドの継続
κ ∈ K  = E → C               式の継続
    K* = E* → C              式の列の継続
ω ∈ O                         出力 (文字の有限列)
    A  = O × (E + X)          答え
    X  = {error}              エラー
```

R5RS との違い:

- **E**: Q, H, Ev, Es を除き、R を Z に置き換えた。
- **Ep**: ペアの書換え (`set-car!` 等) を持たないので、書換え可能フラグ T を除いた (R5RS では `L × L × T`)。
- **K**: 多値がないので、継続は値の列ではなく値を 1 つ受け取る (R5RS では `E* → C`)。
  これに伴い、R5RS の補助関数 `send` と `single` は要らなくなる。
  引数の列を評価するときだけ K* を使う。
- **A**: 出力を表すため、答えを「出力の列」と「最終結果 (値またはエラー)」の組とした。
  R5RS では A の中身を定めていない。
- **X**: エラーの種類を区別しないので、要素が 1 つだけのドメインとした。
  これに伴い、`wrong` はエラーの種類を表す引数をとらない (R5RS では `wrong : X → C`)。

### 8.4 意味関数

```
𝒦  : Con  → E
ℰ  : Exp  → U → K → C
ℰ* : Exp* → U → K* → C
𝒟  : Def* → U → C → C
𝒫  : Prog → A
```

#### 定数

```
𝒦⟦n⟧   = n in E          (n は整数リテラルの表す整数)
𝒦⟦#t⟧  = true
𝒦⟦#f⟧  = false
𝒦⟦'()⟧ = null

ℰ⟦K⟧ = λρκ . κ (𝒦⟦K⟧)
```

#### 変数参照

```
ℰ⟦I⟧ = λρκ . hold (lookup ρ I)
                   (λε . ε = undefined → wrong,
                                          κ ε)
```

#### 手続き呼出し

左から右への評価なので、R5RS の `permute` / `unpermute` は使わない。

```
ℰ⟦(E0 E*)⟧ = λρκ . ℰ*⟦E0 E*⟧ ρ (λε* . applicate (ε* ↓ 1) (ε* † 1) κ)
```

#### lambda 式

```
ℰ⟦(lambda (I*) E0)⟧ =
  λρκ . tievals (λα* . κ (⟨α* ↓ 1,
                           λε*κ′ . #ε* = #I* →
                                      tievals (λα*′ . ℰ⟦E0⟧ (extends ρ I* α*′) κ′) ε*,
                                    wrong⟩
                          in E))
                ⟨unspecified⟩
```

外側の `tievals` は、手続きの目印にする場所を 1 つ確保する。

#### 条件式

```
ℰ⟦(if E0 E1 E2)⟧ = λρκ . ℰ⟦E0⟧ ρ (λε . truish ε → ℰ⟦E1⟧ ρ κ,
                                               ℰ⟦E2⟧ ρ κ)
```

#### 代入

```
ℰ⟦(set! I E)⟧ = λρκ . ℰ⟦E⟧ ρ (λε . hold (lookup ρ I)
                                         (λε′ . ε′ = undefined → wrong,
                                                                 assign (lookup ρ I) ε (κ unspecified)))
```

R5RS では `assign (lookup ρ I) ε (send unspecified κ)` である。
本言語では K が値を 1 つ受け取るので `κ unspecified` と書き、
加えて、まだ値が格納されていない場所への代入を `wrong` にした (4.7 節)。
7.1 節の制約 5 により、I は初期環境の場所を指さない。

#### letrec 式

`I* = ⟨I1, …, In⟩`, `L* = ⟨L1, …, Ln⟩` とする。

```
ℰ⟦(letrec ((I1 L1) … (In Ln)) E0)⟧ =
  λρκ . tievals (λα* . (λρ′ . ℰ*⟦L*⟧ ρ′ (λε* . assigns α* ε* (ℰ⟦E0⟧ ρ′ κ)))
                       (extends ρ I* α*))
                ⟨undefined, …, undefined⟩          (n 個)
```

`Li` はすべて lambda 式なので、`ℰ*⟦L*⟧` の評価中に `α*` の中身を読むことはない。
したがって、ここで `wrong` になることはない。

#### 式の列

```
ℰ*⟦ ⟧      = λρκ* . κ* ⟨ ⟩
ℰ*⟦E0 E*⟧  = λρκ* . ℰ⟦E0⟧ ρ (λε0 . ℰ*⟦E*⟧ ρ (λε* . κ* (⟨ε0⟩ § ε*)))
```

#### 定義の列

```
𝒟⟦ ⟧                    = λρθ . θ
𝒟⟦(define I E) D*⟧      = λρθ . ℰ⟦E⟧ ρ (λε . assign (lookup ρ I) ε (𝒟⟦D*⟧ ρ θ))
```

#### プログラム

`D* = ⟨(define I1 E1), …, (define In En)⟩`, `I* = ⟨I1, …, In⟩` とする。
ρ0, σ0 は初期環境と初期記憶 (8.7 節)、κ0 は初期継続である。

```
𝒫⟦D* E0⟧ = tievals (λα* . (λρ . 𝒟⟦D*⟧ ρ (ℰ⟦E0⟧ ρ κ0))
                          (extends ρ0 I* α*))
                   ⟨undefined, …, undefined⟩       (n 個)
                   σ0

κ0 = λεσ . ⟨⟨ ⟩, ε in (E + X)⟩
```

R5RS では、プログラムの意味を「定義を代入に置き換え、全体を lambda 式で包んだもの」として間接的に定める (R5RS §7.2 冒頭)。
本言語の `set!` はまだ値が格納されていない変数への代入をエラーにするので (4.7 節)、この置き換えは使えない。𝒟 で直接定める。

### 8.5 補助関数

```
lookup  : U → Ide → L
lookup  = λρI . ρ I

extends : U → Ide* → L* → U
extends = λρI*α* . #I* = 0 → ρ,
                   extends (ρ[(α* ↓ 1)/(I* ↓ 1)]) (I* † 1) (α* † 1)

wrong   : C
wrong   = λσ . ⟨⟨ ⟩, error in (E + X)⟩

new     : S → (L + {error})        [実装依存]
          公理: new σ ∈ L ならば σ (new σ | L) ↓ 2 = false

hold    : L → K → C
hold    = λακσ . κ (σ α ↓ 1) σ

update  : L → E → S → S
update  = λαεσ . σ[⟨ε, true⟩/α]

assign  : L → E → C → C
assign  = λαεθσ . θ (update α ε σ)

assigns : L* → E* → C → C
assigns = λα*ε*θ . #α* = 0 → θ,
                   assign (α* ↓ 1) (ε* ↓ 1) (assigns (α* † 1) (ε* † 1) θ)

tievals : (L* → C) → E* → C
tievals = λψε*σ . #ε* = 0 → ψ ⟨ ⟩ σ,
                  new σ ∈ L → tievals (λα* . ψ (⟨new σ | L⟩ § α*))
                                      (ε* † 1)
                                      (update (new σ | L) (ε* ↓ 1) σ),
                  wrong σ

truish  : E → T
truish  = λε . ε = false → false, true

applicate : E → E* → K → C
applicate = λεε*κ . ε ∈ F → (ε | F ↓ 2) ε* κ,
                    wrong

prepend : O → A → A
prepend = λω⟨ω′, r⟩ . ⟨ω § ω′, r⟩
```

引数の個数を検査する補助関数:

```
noarg  : (K → C) → (E* → K → C)
noarg  = λζε*κ . #ε* = 0 → ζ κ, wrong

onearg : (E → K → C) → (E* → K → C)
onearg = λζε*κ . #ε* = 1 → ζ (ε* ↓ 1) κ, wrong

twoarg : (E → E → K → C) → (E* → K → C)
twoarg = λζε*κ . #ε* = 2 → ζ (ε* ↓ 1) (ε* ↓ 2) κ, wrong
```

### 8.6 標準手続きの意味

#### 算術・除算・比較

整数演算 `f : Z → Z → Z` と整数上の関係 `R : Z → Z → T` から、次のように作る。

```
arith  : (Z → Z → Z) → E* → K → C
arith  = λf . twoarg (λε1ε2κ . (ε1 ∈ Z ∧ ε2 ∈ Z) → κ ((f (ε1 | Z) (ε2 | Z)) in E),
                                wrong)

divide : (Z → Z → Z) → E* → K → C
divide = λf . twoarg (λε1ε2κ . (ε1 ∈ Z ∧ ε2 ∈ Z) →
                                  (ε2 | Z = 0 → wrong,
                                                κ ((f (ε1 | Z) (ε2 | Z)) in E)),
                                wrong)

compare : (Z → Z → T) → E* → K → C
compare = λR . twoarg (λε1ε2κ . (ε1 ∈ Z ∧ ε2 ∈ Z) → κ (R (ε1 | Z) (ε2 | Z) → true, false),
                                 wrong)
```

| 変数 | 意味 |
|---|---|
| `+` `-` `*` | `arith (+)`, `arith (−)`, `arith (×)` |
| `quotient` | `divide quo`、ただし `quo n1 n2 = sgn(n1/n2) · ⌊|n1/n2|⌋` |
| `remainder` | `divide rem`、ただし `rem n1 n2 = n1 − n2 · quo n1 n2` |
| `modulo` | `divide mod`、ただし `mod n1 n2 = n1 − n2 · ⌊n1/n2⌋` |
| `=` `<` `>` `<=` `>=` | `compare (=)`, `compare (<)`, `compare (>)`, `compare (≤)`, `compare (≥)` |

#### 述語

```
zero? = onearg (λεκ . ε ∈ Z → κ (ε | Z = 0 → true, false),
                              wrong)
not   = onearg (λεκ . κ (truish ε → false, true))
null? = onearg (λεκ . κ (ε = null → true, false))
pair? = onearg (λεκ . κ (ε ∈ Ep → true, false))

eq?   = twoarg (λε1ε2κ .
          (ε1 ∈ Z  ∧ ε2 ∈ Z)  → κ (ε1 | Z = ε2 | Z → true, false),
          (ε1 ∈ M  ∧ ε2 ∈ M)  → κ (ε1 | M = ε2 | M → true, false),
          (ε1 ∈ Ep ∧ ε2 ∈ Ep) → κ (((ε1 | Ep) ↓ 1 = (ε2 | Ep) ↓ 1 ∧
                                    (ε1 | Ep) ↓ 2 = (ε2 | Ep) ↓ 2) → true, false),
          (ε1 ∈ F  ∧ ε2 ∈ F)  → κ ((ε1 | F) ↓ 1 = (ε2 | F) ↓ 1 → true, false),
          κ false)
```

#### ペア

```
cons = twoarg (λε1ε2κ . tievals (λα* . κ (⟨α* ↓ 1, α* ↓ 2⟩ in E)) ⟨ε1, ε2⟩)

car  = onearg (λεκ . ε ∈ Ep → hold ((ε | Ep) ↓ 1) κ,
                             wrong)
cdr  = onearg (λεκ . ε ∈ Ep → hold ((ε | Ep) ↓ 2) κ,
                             wrong)
```

#### 出力

```
display = onearg (λεκσ . prepend (show σ ε) (κ unspecified σ))
newline = noarg  (λκσ  . prepend ⟨改行文字⟩ (κ unspecified σ))
```

出力は `prepend` によって答えの出力列の先頭に付け加えられる。
したがって、エラーで止まったプログラムの答えにも、それまでの出力が残る。

> 注: この定め方では、停止しないプログラムの答えは ⊥ になり、それまでの出力は答えに現れない。
> 停止するプログラムについては、処理系が出力をその場で逐次書き出しても結果は同じである。

#### 継続

```
cwcc = onearg (λεκ . ε ∈ F → tievals (λα* . applicate ε
                                                   ⟨⟨α* ↓ 1, onearg (λε′κ′ . κ ε′)⟩ in E⟩
                                                   κ)
                                       ⟨unspecified⟩,
                             wrong)
```

- 継続手続きは、`cwcc` が呼ばれたときの継続 κ を持つ手続き値 (F の要素) である。
  呼ばれると、その時点の継続 κ′ を使わずに捨て、受け取った値を κ に渡す。
- `tievals` は、継続手続きの目印 (`eq?` で使う) にする場所を 1 つ確保する。lambda 式の場合と同じである。
- `onearg` により、継続手続きに 1 個以外の引数を渡すと `wrong` になる (6.7 節)。
- proc は `cwcc` 自身の継続 κ で呼ばれる。これが「proc の呼出しは末尾呼出し」であることを表す (3.6 節)。

R5RS の定義との違い:

- R5RS では継続手続きの本体が `λε*κ′ . κ ε*` で、任意個の値を継続に渡す。
  本言語では K が値を 1 つ受け取るので (8.3 節)、`onearg (λε′κ′ . κ ε′)` とした。
- R5RS では目印の場所を `new` と `update` で直接確保している。本言語では同じことを `tievals` で書いた。

### 8.7 初期環境

標準手続きの変数を `p1, …, p22`、それぞれの意味 (8.6 節) を `f1, …, f22` とする。
互いに異なる場所 `α1, …, α22, β1, …, β22` を選び、次のように定める。

```
ρ0 pi = αi
σ0 αi = ⟨⟨βi, fi⟩ in E, true⟩
σ0 βi = ⟨unspecified, true⟩
σ0 α  = ⟨unspecified, false⟩      (その他の α)
```

βi は各標準手続きの目印 (`eq?` で使う) である。
標準手続きの名前以外の識別子に対する ρ0 の値は任意でよい。7.1 節の制約 4 により、そのような識別子は参照されない。

### 8.8 外部表現

`display` が出力する表現を `show : S → E → O` で定める。

```
show σ ε = ε ∈ Z        → (ε | Z) の 10 進表記 (負なら先頭に "-"),
           ε = true     → "#t",
           ε = false    → "#f",
           ε = null     → "()",
           ε ∈ Ep       → "(" § show σ (σ ((ε | Ep) ↓ 1) ↓ 1)
                              § tail σ (σ ((ε | Ep) ↓ 2) ↓ 1),
           ε ∈ F        → 処理系依存 (例: "#<procedure>"),
           ε = unspecified → 処理系依存

tail σ ε = ε = null → ")",
           ε ∈ Ep   → " " § show σ (σ ((ε | Ep) ↓ 1) ↓ 1)
                          § tail σ (σ ((ε | Ep) ↓ 2) ↓ 1),
           " . " § show σ ε § ")"
```

循環構造は作れないので (3.5 節)、`show` は必ず停止する。
`undefined` は変数参照の時点でエラーになるので、`show` に渡されることはない。

## 9. エラーと実装制限

### 9.1 エラー

本言語では、次のエラーはすべて「エラーが通知される」。

| エラー | 検出の時期 |
|---|---|
| 字句・構文の誤り (2 章, 7 章の BNF) | 実行前 |
| 静的制約の違反 (7.1 節 1〜3) | 実行前 |
| 未束縛変数の参照 (7.1 節 4) | 実行前 |
| 標準手続きの名前や未束縛変数への代入 (7.1 節 5) | 実行前 |
| 値が格納される前の変数の参照 | 実行時 |
| 値が格納される前の変数への代入 | 実行時 |
| 手続きでない値の適用 | 実行時 |
| 引数の個数違い | 実行時 |
| 標準手続きの引数の型違い | 実行時 |
| ゼロによる除算 | 実行時 |

エラーの報告は、どのエラーでも同じ形にする。

- 処理系は、エラーが起きたことを示す決まった 1 行 (例: `error`) だけを出力する。
- エラーの種類、発生位置、関係する値などは出力しない。
- 実行前に検出したエラーでも、実行時に検出したエラーでも、出力は同じである。
- 実行時エラーの場合、エラーの前に `display` / `newline` で出力した内容はそのまま残る。

```scheme
(display 1)
(car '())
```

出力 (例):
```
1error
```

エラーの出力先 (標準出力か標準エラー出力か) は処理系が決めてよい。

### 9.2 実装制限

- **記憶不足**: 実装制限の違反を報告してよい (意味論の `tievals` の中の `wrong`)。
- **整数の範囲**: Z は数学的な整数 (上限なし) である。
  処理系は固定長の整数で実装してもよい。
  その場合、演算結果が表現できる範囲を超えたら、実装制限の違反を報告しなければならない。
  範囲を超えた結果を黙って切り捨てたり、折り返したりしてはならない。

実装制限の違反も、9.1 節のエラーと同じ形で報告する。

## 10. 例

### 10.1 階乗

```scheme
(define fact
  (lambda (n)
    (if (= n 0)
        1
        (* n (fact (- n 1))))))
(display (fact 10))
```

出力: `3628800`

### 10.2 逐次実行の補助手続き

本言語には `begin` がないが、評価順序が左から右なので、次の手続きで代用できる。

```scheme
(define seq (lambda (a b) b))
(seq (display 1)
     (seq (newline)
          (display 2)))
```

出力:
```
1
2
```

### 10.3 相互再帰と末尾呼出し

```scheme
(letrec ((even? (lambda (n) (if (zero? n) #t (odd?  (- n 1)))))
         (odd?  (lambda (n) (if (zero? n) #f (even? (- n 1))))))
  (display (even? 1000000)))
```

出力: `#t`

`even?` と `odd?` の呼出しは末尾呼出しなので、処理系は一定の記憶領域でこれを実行できなければならない (3.6 節)。

### 10.4 リスト

```scheme
(define sum
  (lambda (l)
    (if (null? l)
        0
        (+ (car l) (sum (cdr l))))))
(define seq (lambda (a b) b))
(define xs (cons 1 (cons 2 (cons 3 '()))))
(seq (display xs)
     (seq (newline)
          (display (sum xs))))
```

出力:
```
(1 2 3)
6
```

### 10.5 継続による脱出

リストの要素の積を求める。途中で 0 を見つけたら、残りの掛け算をせずに 0 を返す。

```scheme
(define product
  (lambda (l)
    (call-with-current-continuation
      (lambda (return)
        (letrec ((loop (lambda (l)
                         (if (null? l)
                             1
                             (if (zero? (car l))
                                 (return 0)
                                 (* (car l) (loop (cdr l))))))))
          (loop l))))))
(display (product (cons 1 (cons 0 (cons 3 '())))))
```

出力: `0`

`(return 0)` を呼んだ時点で、積まれていた `(* 1 □)` は捨てられる。

### 10.6 代入による状態

呼ぶたびに 1 ずつ大きい値を返す手続きを作る。`n` は `make-counter` の仮引数で、返した手続きがその場所を共有する。

```scheme
(define seq (lambda (a b) b))
(define make-counter
  (lambda (n)
    (lambda ()
      (seq (set! n (+ n 1)) n))))
(define c1 (make-counter 0))
(define c2 (make-counter 100))
(seq (display (c1))
     (seq (display (c1))
          (seq (display (c2))
               (display (c1)))))
```

出力: `121013`

`c1` と `c2` は別々の `make-counter` 呼出しで作られたので、別々の場所 `n` を持つ。

### 10.7 エラーの例

次の各行は、それぞれ単独のプログラムとして実行するとエラーになる。
注釈にはエラーになる理由を書いたが、処理系の出力はどれも同じである (9.1 節)。

```scheme
(car '())             ; 実行時エラー: ペアでない引数
(+ 1 2 3)             ; 実行時エラー: 引数の個数違い
(quotient 1 0)        ; 実行時エラー: ゼロによる除算
(1 2)                 ; 実行時エラー: 手続きでない値の適用
(call-with-current-continuation 1)                    ; 実行時エラー: 引数が手続きでない
(call-with-current-continuation (lambda (k) (k 1 2))) ; 実行時エラー: 継続手続きの引数の個数違い
(define a (set! b 1)) (define b 2) b                  ; 実行時エラー: 値が格納される前の変数への代入
(set! car cdr)        ; 実行前エラー: 標準手続きの名前への代入
(set! z 1)            ; 実行前エラー: 未束縛変数への代入
(lambda (x x) x)      ; 実行前エラー: 仮引数の重複
(if #t 1)             ; 実行前エラー: 構文の誤り (代替部がない)
(letrec ((x 1)) x)    ; 実行前エラー: 構文の誤り (初期値が lambda 式でない)
y                     ; 実行前エラー: 未束縛変数
```

## 11. 未決事項

ドラフトからこの仕様を作る際に、解釈を決めた点と、まだ決まっていない点をまとめる。

1. **「すべて 2 引数固定」の解釈**
   ドラフトの 2 引数固定は、`zero?`・`car`・`display` (1 引数) や `newline` (0 引数) とは両立しない。
   この仕様では「すべて固定個数 (可変長なし)。算術と比較はちょうど 2 引数」と解釈した。
2. **型の一覧**
   ドラフトの 2 つ目の型の一覧には `symbol?` `vector?` `port?` が残っている。
   しかし、ドメイン `E = Z + M + F + Ep`、シンボルを書けない文法、ポート引数のない `display` のどれとも合わない。
   この仕様ではシンボル・ベクタ・ポートの型を除いた。
   シンボルを残す場合は、Q をドメインに戻し、`'<識別子>` を定数として追加する必要がある。
3. **型述語**
   ドラフトにある `null?` と `pair?` だけを入れた。
   `number?` `boolean?` `procedure?` を加えるかどうかは決めていない。
   加えても方針 1 には反しない。
4. **記憶 (store) が要るかどうか (第 3 版で解決)**
   第 2 版までは代入がなかったので、`letrec` を環境の不動点として定めて記憶を除ける可能性があった。
   第 3 版で `set!` を加えたので、記憶は必須になった。
5. **大文字と小文字**
   方針 1 を守るため、R5RS と同じく区別しないことにした。
   区別する (R6RS/R7RS と同じ) ようにすると、実装は簡単になるが、R5RS の部分集合ではなくなる。
6. **未規定値と手続きの外部表現**
   処理系に任せた。処理系の出力を比べたり、テストしたりする都合上、一つに決めたほうがよいかもしれない。
7. **主式の値の扱い**
   出力しないことにした (5.3 節)。
   REPL を提供する場合などには、別途定める。
8. **継続 (第 2 版で追加)**
   `call-with-current-continuation` を標準手続きとして加えた (6.7 節, 8.6 節)。決めた点は次のとおり。
   - 名前は R5RS の `call-with-current-continuation` だけとし、`call/cc` は持たない (方針 1)。
   - 継続手続きはちょうど 1 引数とした。多値がなく、K が値を 1 つ受け取ることに合わせた。
   - 何度でも呼び出せる継続 (multi-shot) を要求する。one-shot や escape-only の実装は認めない。
   - `dynamic-wind` は持たない。
   継続を加えたことで、定義の再実行による再格納が起こりうるようになった (3.5 節)。
9. **代入 (第 3 版で追加)**
   `set!` を原始式として加えた (4.7 節, 8.4 節)。決めた点は次のとおり。
   - 代入できるのは変数だけとした。`set-car!` / `set-cdr!` は持たず、ペアは書換え不可能のまま (Ep に T を戻さない)。
     このため循環したリスト構造は引き続き作れず、`show` は必ず停止する。
   - 初期環境で束縛されているだけの標準手続きの名前への代入は、実行前エラーとした (7.1 節の制約 5)。
     R5RS では許されるが、禁止しても方針 1 には反しない。
     これにより、定義し直されていない標準手続きの名前が指す値は、実行中ずっと変わらないことが保証される。
   - まだ値が格納されていない `define` の変数への代入は、実行時エラーとした (R5RS §5.2.1 に合わせる)。
     `lambda` と `letrec` の変数は、`set!` 式が評価される時点で必ず値を持つので、この検査は `define` の変数にしか効かない。
   - `set!` 式の値は未規定値 (`display` の値と同じ M の要素 `unspecified`) とした。
   - `letrec` は原始式のまま残した。R5RS のように `set!` を使った派生式にはしない。
     初期値を lambda 式に限る制限 (4.6 節) を保ち、代入されない `letrec` 変数を処理系が書換え不可能として扱える余地を残すためである。
   - 処理系は、代入される変数を box に入れるなどして、手続きが場所を共有するように実装する必要がある (3.5 節)。
     どの変数が代入されるかは構文から静的に分かる (`set!` の対象の変数とその束縛を見ればよい)。
